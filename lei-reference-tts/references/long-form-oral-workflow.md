# Long Form Oral TTS Workflow

适用于长文稿、视频口播、观点表达类文案。

## 目标

把用户原文处理成适合 `IndexTTS2 + Lei voice` 的长口播音频：

1. 先把原文改成口语表达
2. 补足停顿、断句、语气词
3. 按情绪段落分段，而不是固定字数硬切
4. 每段单独设情绪参数
5. 保持整体情绪曲线自然、连续
6. 最后拼接成完整 `wav`

## 口播润色规则

- 优先改成“人在讲”的感觉，而不是“文章在写”的感觉
- 常用口语缓冲词：`啊`、`嗯`、`其实`、`说实话`、`你想啊`、`我觉得`
- 长句必须拆开，避免一口气读到底
- 关键节奏处要补标点：`，` `。` `；` `：`
- 可以少量加入空格，帮助停顿更稳定
- 避免每句都很满，要留一点呼吸感
- 不要堆太多感叹号，保持可信、自然

## 分段规则

- 按观点转折、情绪转折、场景转折来切
- 每段最好能独立成立一个小论点
- 常见分段点：
  - 开场 / 定义
  - 亮点 / 吸引力
  - 问题 / 风险
  - 机会 / 判断
  - 预测 / 收束

## 情绪参数原则

- 默认用 `vector` 模式，最稳定
- 8 维顺序固定：
  `[高兴, 愤怒, 悲伤, 害怕, 厌恶, 忧郁, 惊讶, 平静]`
- 推荐总原则：
  - 开场：轻兴奋 + 轻惊讶 + 适度平静
  - 亮点：提高高兴、惊讶
  - 问题：降低高兴，少量愤怒/悲伤/忧郁
  - 机会：回升高兴和惊讶
  - 收束：中高兴奋，但保留平静

## 连续性约束

- 相邻两段 `emo_alpha` 差值尽量不超过 `0.10`
- 相邻两段主情绪变化尽量小步过渡
- 不要从“很平”直接跳到“很炸”
- 对负面段落也不要过度拉高愤怒，避免失真

## 建议区间

- 日常说明：`emo_alpha 0.54 - 0.60`
- 明显兴奋：`emo_alpha 0.60 - 0.68`
- 风险/问题：`emo_alpha 0.52 - 0.58`
- `平静`维通常保留 `0.10 - 0.18`
- `惊讶`维通常保留 `0.03 - 0.16`

## 工程文件

建议产出 3 份文件：

1. `*_segments.txt`
   - 只放润色后的分段口播文案
2. `*_project.json`
   - 每段文案 + 每段情绪参数
3. `*_full.wav`
   - 最终拼接好的完整音频

## 推荐执行顺序

1. 用户给原文或文件
2. 先人工/模型润色成口播分段稿
3. 用 `scripts/scaffold_long_form_project.py` 生成第一版 project
4. 视文案微调情绪参数
5. 用 `scripts/synthesize_project.py` 合成
